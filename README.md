# 抖音视频合规检查 · douyin-compliance-check

> 发布前把这条内容过一遍，比发布后申诉划算。

一个抖音发布前的内容合规自查 Agent Skill。把标题、口播稿、正文、话题标签、简介、置顶评论一并核过，必要时解析成片，按抖音官方公开规范判风险等级，并直接给出改写后的文案。

**不限账号、不限品类。** 通用版按通用标准判定；填入账号信息卡后，自动套用对应的品类加严规则。

---

## 它解决什么问题

发布前自查这件事，难在四处：

| 难处 | 具体表现 |
|---|---|
| **规则散** | 官方条款散落在社区自律公约、创作者管理规范、专项治理公告等多份文件里，没有一份"全部规则的合集" |
| **变化快** | 专项治理的点名方向每隔数月即调整，旧笔记与二手攻略常年停留在上一版 |
| **后果重** | 单条下架是轻的，账号信用分、限流、禁止发布、永久封禁逐级递进 |
| **组合更要紧** | 真正落到封禁一级的，几乎都是**组合触发**，而非单句措辞 |

第三条与第四条是本技能的核心判断：

**三类高频违规组合**（公开案例中反复出现）

| 组合 | 常见后果 | 关键判断 |
|---|---|---|
| 引流性表述 ＋ 低质画面 ＋ 平台规则类敏感话题 | 封禁级 | 三者叠加。**只改措辞、不改画面，风险不降** |
| 纯录屏或模板图文 ＋ 工具或产品推荐 | 判软广，推荐量趋零 | 此时措辞往往已经合规，**问题出在画面形态** |
| 同题材改为真人出镜 | 推荐恢复正常 | 正向经验：真人出镜可降低营销判定 |

由此确定审核顺序：**先确认画面形态，再谈措辞。** 这是顺序问题，不是并列问题——画面形态不过关时，措辞改得再干净也没用。

## 检查什么

**十一类风险**

| # | 类别 | 要点 |
|---|---|---|
| 1 | 站外引流与私域导流 | 联系方式、跨平台引导、变体规避；被点名品类按最高级处理 |
| 2 | 低质内容与画面形态 | 录屏、模板图文卡片、搬运、时长过短 |
| 3 | AI 内容标识 | 须按平台要求作自主声明；累计未标会限制曝光 |
| 4 | 极限词与广告法 | 绝对化用语、效果承诺、虚构原价、效果对比图 |
| 5 | 高危题材 | 医疗、金融、法律、封建迷信、危险行为、灰产 |
| 6 | 虚假营销与摆拍 | 虚构演绎须标注，且不得借演绎实施误导 |
| 7 | 版权与素材 | 影视片段、背景音乐、肖像、声音、二创加工不足 |
| 8 | 商业内容与特殊类目 | 报备义务、站外成交、价格可核验、诱导互动 |
| 9 | 未成年人保护 | 不得出镜带货、不得代言与其年龄不符的商品 |
| 10 | 同质化与账号生态 | 批量炮制、模板化文案、画风重复；批量扫描给出相似度量化 |
| 11 | 全链路 | 简介、置顶评论、私信话术、直播口播同属巡检范围，不要只查正文 |

**四级判定**：必改 / 建议改 / 提醒 / **建议放弃选题**。

第四级是本技能独有的一档——**有些选题的属性能量无法通过改写得掉**（例如"教人获取某项能力"＋无人无实景画面的组合），此时如实告知换选题，而不是给一份看着干净、实则仍会出问题的改写稿。

**八类加严清单**（`references/categories.md`）：医疗健康、金融理财、科技与 AI 工具、教育与培训、带货与商业内容、房产、招聘与兼职、母婴与儿童消费品。每类给出资质前置要求、禁语与安全写法对照。

**AI 生成声明检查**：扫描器会在文案里查找生成类信号（AI 生成、AI 配音、数字人、AI 绘画等）与明确披露句（由 AI 生成、本视频由…AI 等）。**检出信号而未检出披露句时会提示补充声明**；已声明时不报——「本视频由 AI 生成」这类披露句本来就该零命中。

## 三类用法

**模式 A · 只审文字**（日常推荐）

文案在草稿阶段就审，不要等到成片——那时改措辞要重录，改画面要重剪。

```bash
python scripts/scan_text.py 文案.txt --category ai
```

多字段输入（标题、口播、标签、简介分别标位置，避免"以为查了其实没查"）：

```bash
python scripts/scan_text.py --json-input draft.json
```

`draft.json`：

```json
{
  "category": "ai",
  "fields": {
    "标题": "……",
    "口播": "……",
    "标签": "#a #b",
    "简介": "……"
  }
}
```

**模式 B · 批量扫一整套草稿**

```bash
python scripts/scan_text.py <目录> --category <品类> --json --out report.json
```

批量内置三项能力，不需要自己写循环：

| 能力 | 说明 |
|---|---|
| 目录递归扫描 | 目录下所有 `.txt / .md / .json / .srt` 逐个扫描，报告字段名带文件名前缀以示来源 |
| 结构化草稿自动识别 | 遇到含 `fields` 的 JSON 草稿，自动按多字段解析，不当纯文本处理 |
| **同质化相似度** | 两两计算字符 3-gram Jaccard 相似度，列出 ≥ 0.30 的组合，识别"同一套模板换皮" |

**模式 C · 解析成片**（涉及画面形态问题时）

```bash
python scripts/extract_video.py --video 成片.mp4 --model small
```

产出写入 `<成片目录>/_review/`：口播转写与字幕、关键帧、关键帧拼图、画面文字、人读汇总与机器可读汇总。

脚本只给数据，**画面形态的判断必须看拼图**：

1. 打开 `contact_sheet.jpg`；
2. 看有无真人面部、有无录屏特征（状态栏、鼠标指针、竖向黑边）、是实景拍摄还是模板化图文卡片；
3. 结合汇总里的人脸检出占比——确认为 0 即按"无真人出镜"处理。

> 🔒 **语音模型默认不联网。** 脚本定位是纯本地解析、素材不出本机；本地没有模型时不会自动下载，
> 而是如实报出并给出补齐方式，确需联网须显式加 `--allow-network`。
> 完整的依赖安装、参数与产出解读见 `references/video-guide.md`。

## 账号信息卡（可选，但建议填一次）

本技能**不绑定任何账号**。但同一个做法在不同账号上的后果不同——千粉新号与百万粉带货号，同样的措辞触发处置的级别可能差一档。

首次使用时把账号情况填进 `references/account-profile.md`，后续自动套用。**不填也能用**，此时按通用标准审，报告里会注明。

需要填四项：**品类**（影响最大的一项）、量级与形态、内容形态、账号状态。其中"账号状态"若为近期有违规记录，会触发**整体上调一档**。

## 依赖

| 脚本 | 依赖 |
|---|---|
| `scan_text.py` | **零第三方依赖**，纯 Python 标准库 |
| `extract_video.py` | `ffmpeg`（必需，抽帧与音轨）；`faster-whisper`（口播转写）、`OpenCV`（人脸检出）、`Pillow`（画面信号）、`tesseract`（画面取字）均为**可选增强，缺哪项就降级跳过哪项** |

转写模型默认 `small`。有本地模型缓存时走离线加载，**默认不外连**。

## 使用边界

- **不判**平台的实际算法判定结果。本技能是**发布前的规则自查**，不是平台审核的替代，也不构成法律意见。
- **不做**代写选题、代发内容，也**不承诺"改完必过"**。
- 平台判定权在平台。本技能据公开规范给出**风险提示与改写建议**，使用者对发布结果自负其责。

## 规则依据与时效

规则依据核对至 **2026-09-25**；**判据口径修订于 2026-09-26**（v2.0.0）。
逐条标注来源与核对级别（`references/platform-rules-sources.md`）。

平台规则变动频繁，**超过一个月未更新须重新核对**。该文件同时列出复核清单，并写明一条自用规矩：**带 AI 生成声明的网页内容不得作为依据**。
