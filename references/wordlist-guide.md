# 词表使用说明

> 对应 `references/wordlist.json`。本档解释字段含义、判定逻辑与扩词方法。
> 不看本档也能用，但要改词表、或想弄清「为什么这句报了／没报」，须看本档。

---

## 一 整体结构

```json
{
  "meta":          { "版本、更新日期、适用范围、变更记录" },
  "tier_a":        { "绝对红线：出现即判" },
  "tier_b":        { "组合触发：须共现" },
  "tier_c":        { "视上下文" },
  "tier_d":        { "绝对化用语（含构式与白名单）" },
  "category_extra":{ "8 个品类的附加条目" },
  "cooccur":       { "共现强度参数" },
  "ai_disclosure": { "AI 声明检测词集" },
  "suppress_rules":{ "误报抑制与加重情节" },
  "context_words": { "辅助词集" },
  "replacements":  { "改写对照表" }
}
```

## 二 四级判定

| 档位 | 判定方式 | 输出等级 |
|---|---|---|
| **A 档** | 出现即判，不看上下文 | 🔴 必改 |
| **B 档** | 须与行动词或产品名**共现**才判 | 🔴 共现则必改；未共现则 🟢 |
| **C 档** | 须与指定语境共现才升级 | 🔴／🟡 共现则升级；否则 🟢 |
| **D 档** | 绝对化用语 | 🟡 建议改 |

**为什么要分级，而不是一张禁用清单？**
一刀切的清单会把「评论区交流」「第一次」「万能提示词」这类普通表述全报成必改。
**误报一高，使用者就不用了**——分级与抑制不是锦上添花，是这个工具能不能被用起来的前提。

---

## 三 共现强度（`cooccur` 段）

B／C 档的触发词与所需语境（`require`）之间，**不是「全文任意位置命中就算共现」**。
按距离分三档：

| 强度 | 条件 | 处理 |
|---|---|---|
| **strong** | 同一小句，或同一句内 | 按条目原级执行 |
| **weak_medium** | 跨句，但相距在 `cross_sentence_max_chars`（默认 100 字）以内 | **降一级**，并标注「跨句共现，须人工复核」 |
| **weak / none** | 相距超过上限，或全文未命中 `require` | 不判风险，仅作提示 |

**为什么要有距离上限？**
一篇两千字的文案，开头写「免费」、结尾写「链接」，中间隔了一千多字，若仍算共现，
就会把两处无关表述拼成一条假风险。有上限之后，只有真正靠近的组合才升级。

## 四 误报抑制（`suppress_rules` 段）

### 4.1 抑制词的作用域是**小句**，不是整句

命中词所在的小句内出现否定词或规则引用词，才降一级。

**反例（改之前）**：「学不会不要钱，保证包过」——整句含「不要」，导致后半句的真红线
「包过」被一并降级。这正是抑制规则最容易出错的形态：**一个否定词把不相关的红线也放过了**。

**小句切分规则**：按 `。！？!?` 换行、逗号、分号、冒号切分。
**顿号「、」不作为分隔符**——它用于并列，不改变语义完整性；
若把「禁止刷单、赌博」切成两段，「赌博」就会因所在段无否定词而不再被抑制。

### 4.2 否定词表

`不要｜不能｜禁止｜避免｜别｜不该｜切勿｜不得｜严禁｜勿｜无需｜不用｜并非｜不是｜不算｜不保证｜不承诺｜不能保证｜未必｜不一定｜不可以｜不可｜拒绝｜抵制｜谨防｜警惕｜提防｜小心｜防止｜戒掉｜远离`

> 注意：**没有收录裸「无」「非」「未」「没有」**。因为「无风险」「无效退款」中的「无」
> 本身就是承诺词的一部分，收录它们会把真红线放过。

### 4.3 加重情节（`escalate_exceptions`）

「绕过／规避／躲过／避开 ＋ 审核／检测／风控」这类组合，**不适用抑制，且须优先处理**。

**为什么单列**：抑制规则里含「审核」一词，本意是让「讲合规规则本身」不误报。
但「私信我绕过平台审核」也含「审核」，结果反被降级——**抑制规则与加重情节撞车**。
故此处规定：出现规避类组合时，以加重情节为准。

## 五 绝对化用语的构式与白名单（`tier_d` 段）

| 字段 | 作用 |
|---|---|
| `pattern` | 显式词表 |
| `construct` | 「最 ＋ 形容词」构式，用**有限形容词集合**，不用无差别「最」字 |
| `whitelist` | 白名单，命中即不计。按**正则前缀**匹配，可写负向断言 |

**两个刻意的限定**：

- **「第一」带负向断言**：只保留「第一名」「全网第一」这类排名用法，放行「第一步」「第一次」等序数；
- **「万能」限定为医药语境**：只报「万能神药／万能药／万能疗法」，放行「万能提示词」「万能公式」。

这两处限制不是拍脑袋定的：**对真实文案做回归时，一段正常的 AI 工具口播因这两处被误报两处**，故加限定。

**为什么不用无差别「最Ｘ」构式**：那样会把「最重要」「最常见」「最怕」全部报红。
基于形容词集合的写法，既覆盖了「最恐怖」「最快」这类真正的绝对化评价，又不伤及普通叙述。

## 六 AI 声明检测（`ai_disclosure` 段）

| 字段 | 作用 |
|---|---|
| `signals` | **生成类信号**：AI 生成、AI 配音、数字人、AI 绘画等 |
| `declarations` | **明确披露句**：由 AI 生成、本视频由…AI、内容由 AI 等 |

**判定**：命中 `signals` 且未命中 `declarations` → 报告提示补充声明。

**两项必须分清**：

1. **已声明时零命中是正确行为**，不能报——「本视频由 AI 生成」本来就不该被报；
2. **声明的判定必须用句式，不能用裸词**。曾经把「AI生成」「数字人」列为声明词，
   结果「我用 AI 生成的画面做了这个视频」被判成「已声明」而漏提示——**把描述当成了披露**。

> 本项是**提示**，不是判定。扫描器无法确知成片是否真用了 AI，只能据文案信号提醒确认。

## 七 同质化相似度

批量扫描多个文件时，脚本会两两计算**字符 3-gram Jaccard 相似度**并列出 ≥ 0.30 的组合。

| 数值 | 含义 |
|---|---|
| ≥ 0.55 | 高度相似，基本可判定为同一套模板 |
| 0.30 ~ 0.55 | 较相似，须核对结构是否雷同 |

用 `--no-similarity` 可关闭。单文件扫描时不做此项。

## 八 怎么扩词（重要）

**扩词是这套东西最容易出错的地方。** 按以下次序做：

### 8.1 先定档位

| 想加的表述 | 该进哪档 | 判据 |
|---|---|---|
| 违法或平台明文禁止（联系方式、赌博、保证性承诺） | **A 档** | 无论上下文都不该出现 |
| 与行动词组合才致险（下载、领取、评论区导流） | **B 档** | 单独出现是正常表达 |
| 特定语境下才成问题（收益、平台规则、医疗） | **C 档** | 提及无害，提供建议才越线 |
| 夸大但不违法（最强、第一、独家） | **D 档** | 统一建议改，不判必改 |

**没想清档位就加，是误报的主要来源。**

### 8.2 加完必做三件事

1. **跑正例**：新词该报的，是否报出来了；
2. **跑反例**：一批**正常文案**（最好是真实素材）是否被新词误伤；
3. **跑边界**：否定语境、引用规则、跨句共现三种情形，等级是否正确。

> ⚠️ **只用自造的违规例子做验证，是测不出误报的**——你必须拿真实文案跑一遍。
> 本词表的「万能」「第一」两处限定，正是真实文案回归才发现的。

### 8.3 一条纪律

**规则文档里写了的判据，词表里必须有对应条目，反之亦然。**
曾经出现过：文档把「营造虚假紧俏」标为🔴出现即判，词表却把它放在共现档，
实测「最后三件了，马上涨价」只报提醒——**同一份东西自己跟自己矛盾**。
改完任一处，必查另一处。

## 九 字段速查

| 字段 | 出现在 | 含义 |
|---|---|---|
| `id` | A／B／C 档、品类条目 | 唯一标识，用于报告归并 |
| `label` | 全部 | 人读名称 |
| `pattern` | A 档、品类条目 | 出现即判的正则 |
| `trigger` | B／C 档 | 触发词正则 |
| `require` | B／C 档 | 须共现的语境正则 |
| `level` | 全部 | `red` / `yellow` / `green` |
| `advice` | 全部 | 处置建议 |
| `note` | 部分 | 设计说明，说明该条为何这样写 |
