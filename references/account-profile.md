# 账号信息卡

> **用途**：本技能不绑定任何账号。填写本卡后，每次审核自动套用；**不填也能用**，此时按通用标准判定，报告里注明"未配置账号信息"。
> **填写方式**：直接在本文件表格里填，或另存一份 `account-profile.local.md`（多账号分别存）。
> **隐私提示**：本卡只填审核所需的**属性**，不必填账号名、抖音号、粉丝实名信息等可识别信息。若填了，注意 `account-profile.local.md` 不要随技能一起分发。

---

## 一、基本信息（四项，都很短）

| 项 | 填写 | 说明 |
|---|---|---|
| **品类** | 〈见下方取值〉 | **影响最大的一项**，决定套用哪套品类加严规则 |
| **账号类型** | 〈个人号 / 企业号 / 机构号〉 | 企业号与机构号的标准更严，且需注意资质公示 |
| **内容形态** | 〈真人出镜为主 / 录屏或图文卡片为主 / 混剪 / 混合〉 | 决定画面形态检查的侧重 |
| **账号状态** | 〈正常 / 新号起量期 / 近期有违规记录或刚解封〉 | 后两者触发**标准整体上调一档**（见 SKILL.md 4.3） |

**品类取值**（对应 `categories.md` 与词表的 `category_extra`）：

| 取值 | 品类 |
|---|---|
| `ai` | 科技与 AI 工具 |
| `finance` | 金融理财 |
| `medical` | 医疗健康 |
| `education` | 教育与培训 |
| `ecommerce` | 带货与商业内容 |
| `realestate` | 房产 |
| `recruit` | 招聘与兼职 |
| `maternal` | 母婴与儿童消费品 |
| `none` | 不属上述品类，按通用标准 |

> **可多填**：跨品类时填多个（如 `ecommerce,education`），叠加执行。

---

## 二、可选补充（填了更准，不填不影响）

| 项 | 填写 | 作用 |
|---|---|---|
| 主要变现方式 | 〈无 / 带货 / 星图商单 / 引流私域 / 课程〉 | 判断是否适用商业内容与报备要求 |
| 是否有对应资质 | 〈有（类别）/ 无〉 | 涉及医疗、金融、教育、房产、招聘时**必填** |
| 常用素材来源 | 〈自拍 / 录制屏幕 / 平台素材库 / 外部素材〉 | 提前识别版权与低质风险 |
| 是否使用 AI 生成元素 | 〈AI 配音 / AI 画面 / 数字人 / 无〉 | 若"有"，则**每条都需检查标注** |
| 发布频率 | 〈每天几条〉 | 判断同质化与节奏风险 |
| 历史违规记录 | 〈无 / 有（类型与时间）〉 | 决定是否上调标准 |

---

## 三、填好之后怎么用

1. **模式 A（文字审核）**：把品类传给脚本，附加条目自动叠加

   ```
   python scripts/scan_text.py <文案文件> --category ai
   ```

2. **模式 B／C**：脚本不读本卡，审核时**人工把本卡的状态项带进判定**（尤其是"账号状态"与"是否有资质"两项）。

3. **报告里体现**：在输出开头的"账号品类""账号状态"两行填上（见 `assets/report-template.md`）。

---

## 四、多账号场景

若同时运营多个账号（不同品类、不同状态），**各存一份卡**：

```
account-profile.local.md          # 主号
account-profile.work.local.md     # 工作号
```

审核时按当前账号选用对应的卡。**不要把两个账号的规则混用**——尤其是品类不同时，加严条目差异很大。

> ⚠️ **跨平台注意**：若同一内容还会发到其他平台，**不要假设抖音的判定结论适用于其他平台**。规则不可迁移，见 `references/compliance-rules.md` 第 19 节。
